Uber 在三季度财报电话会上表示，10 月最繁忙的万圣节周仅 4 次用车由 AI 智能体下单，Uber Eats 也只有 500 单智能体订单，同期平台总订单量约 3.2…



![程序员 reaction：还不滚去学习](https://iili.io/CUykzfj.png)
> 3.2 亿分母里的 4



这个数字来自 CFO Balaji Krishnamurthy 对华尔街分析师的直接回应。CEO Dara Khosrowshahi 补充了一句：「非常早期，非常有限」，并表示公司希望未来获得更多增长。同周 DoorDash 也在财报会上称收到几百单智能体订单。Instinct 估值已超百亿美元、Meta Muse 破千万用户——Uber 这份数据与这些热钱叙事之间，存在明显的认知落差。

### 3.2 亿 vs 4：数字背后的叙事落差

叙事落差的根源不在于智能体技术不够强，而在于一个结构性前提：目前进入 Uber 平台的 AI 智能体，几乎都是「外部调用」。也就是说，用户不是在 Uber App 里直接用智能体下单，而是通过 Meta Muse、OpenAI Dots 或 Instinct 这样的第三方助手发起请求，再由助手去调用 Uber API。

这个调用链路上至少有三层损耗：用户意愿（愿不愿意让助手帮忙叫车）、助手能力（能不能正确理解时间和位置信息并调用接口）、平台接受度（Uber 对外部智能体的转化率支持程度）。任何一层卡住，结果都是零。

Halloween 是 Uber 全年 busiest week 之一，3.2 亿订单体量说明需求端没有被削弱——消费者在照常叫车和点餐，只是没通过智能体。换言之，问题不是智能体抢不走生意，而是绝大多数用户还没有把智能体纳入自己的下单路径。

### 智能体下单链路：比想象的多一道摩擦



![智能体下单链路各环节损耗示意](https://iili.io/nLBOzWN.png)
> 智能体下单链路各环节损耗示意



每个箭头代表的不是技术难题，而是用户习惯迁移成本。Uber 自己的数据显示，App 内叫车平均只需 50 秒，常点餐食约 90 秒。智能体下单需要用户先信任助手、再信任输出结果，这中间多出来的决策环节，是目前转化率低的直接原因。

### 平台策略：开放接入但不焦虑

Uber 的公开立场很明确：愿意与第三方智能体合作，但不会把每一种新渠道都视为同等优先级。One 会员约 5500 万，贡献了出行和配送业务总预订额的一半以上，这些高价值用户的保留策略直接挂钩的是「Uber 自有体验」，而不是任意一个外部助手。

这意味着 Uber 的开放是有边界的——智能体可以接入，但要通过新增需求来证明价值，同时不能损害客户体验或现有直接关系的经济效益。DoorDash 同样如此，几百单的量级说明两家平台都在用同一套判断框架：先观察，不押注。

从产品角度看，这个策略是合理的。智能体下单目前的主要障碍不在技术，而在用户心智——没有人因为「有智能体可用」而改变下单习惯。等用户心智发生迁移，平台再调整接入策略，风险更低、主动权更强。

### 边界判断：什么时候这个结论会失效

4 单这个数字的有效性是有条件的。它只反映了万圣节周这一特定场景、特定时段的数据，且当前智能体用户基数本身极小——如果基数放大一百倍，400 单的转化路径会完全走通，结果也会不同。

结论适用的边界是：在智能体尚未形成用户规模效应、且主流用户仍通过原生 App 下单的阶段，平台无需提前调整渠道优先级。一旦智能体在某个高频场景（比如每日通勤叫车、固定餐厅订餐）形成稳定转化路径，Uber 的策略很可能会从「开放观察」转向「主动布局」。

现在下结论说「智能体去中介化失败」为时过早。更准确的说法是：智能体进入生活服务的转化链路，还需要跨过用户习惯这道门槛。技术本身已经够用了。

这个数字看上去像是笑话，但把智能体下单的实际链路拆解开，你会发现中间有四道硬摩擦。



![智能体下单链路卡点](https://iili.io/nLBeHkG.png)
> 智能体下单链路卡点



第一道摩擦在意图到 API 的转译。智能体需要把用户自然语言转化成 Uber 的 API 参数：出发地、目的地、车型、时间。这里涉及地理编码的精度问题——用户说"地铁站口"，系统得把它映射到经纬度。一旦语义理解出现偏差，就会触发补全对话，用户被打断两次以上，转化率就掉下来了。

第二道摩擦是验证与风控。Uber 为了防刷单和欺诈，设置了多重验证环节。智能体在没有完整身份认证的情况下，很容易被风控系统拦截。DoorDash 财报电话会也提到，他们收到的几百单智能体订单里，相当一部分在验证环节流失。

第三道摩擦是支付。智能体可以完成下单，但支付通常需要用户主动确认或预先绑定支付方式。这一步跳出率很高，因为用户不确定智能体是否会乱扣费。

`更狠的是，每道摩擦都在消耗用户耐心。` 一次顺利的叫车平均 50 秒，智能体下单如果反复被打断，整体时长可能超过 3 分钟。用户自然回归 App 原生流程。

平台这边的策略选择很有意思。Uber CEO Dara Khosrowshahi 没有否认智能体的价值，他说的是"非常早期"。这句话的潜台词是：开放接入，但不押注。

具体来说，Uber 的策略是分阶段开放。第一阶段允许智能体调用基础叫车 API，第二阶段才会开放更多个性化选项。这种节奏把控的逻辑在于：先在可控范围内测试智能体的实际表现，再决定是否加大投入。

DoorDash 的策略几乎一致。两家公司都不焦虑，因为他们的核心判断是：用户忠诚度建立在产品体验上，而不是下单渠道上。

这个判断什么时候会失效？有两个条件需要同时变化。

第一个条件是智能体完成身份绑定的比例大幅提升。如果用户愿意提前在智能体里完成支付绑定和地址保存，第二、三道摩擦就会消失。

第二个条件是平台侧的 API 权限开放程度。目前 Uber 的第三方调用限制较多，如果未来开放更接近原生体验的接口，智能体的转化率会显著提升。

目前这两个条件都不成熟。Instinct 估值百亿美元、Meta Muse 突破千万用户，说明资本和流量端很热。但下单链路的实际转化数据告诉我们，技术和体验的冷板凳还很长。

如果你是智能体产品的负责人，现在应该做什么？三个动作：

第一，找 Uber 或 DoorDash 的开发者文档，实测一次完整下单流程，记录所有卡点。不要只看 Demo，要看真实报错。

第二，优化意图解析的容错率。允许用户用模糊表达，智能体主动补全而非反问。

第三，在支付环节做预授权而不是实时扣款。降低用户的不确定性感知。

数据不会骗人，但解读数据需要看清背后的链路。4 单和 500 单不是终点，是起点。

## 数字背后的叙事落差

第一道在意图解析。用户说「帮我叫辆车去市中心」，语义上无法确定取送点、车型偏好、支付习惯；智能体要么反问确认，要么猜一个默认值——两种结果都会增加下单时长。

第二道在 API 调用。Uber 的预约接口并非标准 REST，参数结构复杂，且部分字段（如车型匹配、司机端状态）需要实时查询才能填充完整。

第三道在参数补全。DoorDash 的财报电话会显示，他们同样只收到几百单智能体订单，多数用户最后还是在原生 App 里完成下单。补全对话本身就是留存漏斗的一部分。

第四道在风控拦截。即使金额很小，智能体触发的订单也可能命中年龄验证或地址核验规则，直接转人工流程。

这个数字看起来像是市场过热后的冷水，但把它还原成一组对比，才能看清楚背后的机制。

## 智能体下单链路：比想象的多一道摩擦

数字低不代表智能体没有潜力，问题在于从用户意图到订单完成之间，有几道真实的摩擦。

智能体下单不是简单的「说一句话就有车来」。一个完整的智能体调用链路，至少需要经过四道关卡：语义解析、API 调用参数补全、风控验证、最终提交。每一道都可能打断用户预期中的「一句话说完」体验。



![智能体下单链路卡点](https://iili.io/nLBk96P.png)
> 智能体下单链路卡点



相比之下，Uber App 内叫车的平均用时是 50 秒，选择常点餐食约 90 秒。智能体下单要想形成替代，必须在这两个数字以下完成从意图到订单的全过程。目前的现实是，中间的多轮澄清、参数补全和风控拦截，让总耗时往往超过 2 分钟。

DoorDash 上周也在财报会上称，迄今只收到几百笔来自 AI 智能体的订单。两家头部平台的数据方向一致，说明这不是单家公司的问题，而是整个智能体在交易场景中的通用瓶颈。

## 平台策略：开放接入但不焦虑

Uber 的做法相对克制。公司明确表示愿意与第三方智能体合作，让服务更容易被调用，但前提是智能体必须带来新增需求，且不能损害客户体验或现有服务的直接关系。

Uber One 会员约有 5500 万名，贡献了出行和配送业务合计总预订额的一半以上。这个会员体系的价值在于，它将外部智能体的分发与保留直接关系挂钩——也就是说，Uber 不是在开放一个无差别的下单入口，而是在筛选那些能带来增量价值的渠道。



![Uber 智能体合作策略路径](https://iili.io/nLBkpOG.png)
> Uber 智能体合作策略路径



这种策略的本质是：平台不拒绝外部流量，但要求外部流量必须为平台创造净增量。对 Uber 而言，App 内的叫车体验已经足够简洁，智能体带来的「自然语言下单」优势在高频、低客单价的订单场景中并不明显。

更狠的是，每年能省下一个亿的那种智能体，首先得有人用它。

## 边界判断：什么时候这个结论会失效

4 单叫车这个数字，在以下前提下成立：单平台、低复杂度、时效敏感的下单场景。一旦条件变化，结论也需要调整。

第一种情况是跨平台比价场景。当用户需要在 Uber、Lyft、 DoorDash 等多个平台之间选择时，单一 App 内的 50 秒体验就不再是优势，反而成为信息孤岛。此时，一个能同时调用多个平台 API 的智能体才有替代价值。

第二种情况是预订复杂度提升。从叫一辆车变成预订多人行程、多目的地拼车，或者预订酒店加出行组合，智能体的多步骤编排能力才能显现价值。Uber 的产品负责人曾在采访中强调公司不想成为「为所有人提供一切」，这意味着复杂场景的编排可能优先通过 API 开放给第三方智能体。

第三种情况是模型推理延迟下降。当前智能体下单链路的卡点之一是多轮澄清导致的耗时。当模型的上下文理解能力提升、参数补全变得隐式自动化，下单链路可以从平均 2 分钟压缩到 50 秒以内，替代效应才会开始显现。

目前来看，这三种条件均未成熟。Uber 的 3.2 亿订单对 4 单智能体订单的比值，在未来 12 个月内大概率保持高位，但智能体订单的绝对量会随产品迭代缓慢上升。平台不会恐慌，也不会主动放弃这一渠道——它只是在观察。
