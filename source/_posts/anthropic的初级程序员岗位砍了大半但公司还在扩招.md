## Anthropic 的「反直觉」账本：初级岗砍了，人还在涨

### 27% 降到 9% 的背后

Anthropic 10 月 16 日发布了一份内部就业研究报告，追踪的是公司自身的数据。2025 年初，新招聘的技术人员中有 27% 属于初级岗位；到 2026 年，这个数字降到了 9%。初级员工占技术部门总人数的比例，从 21% 降到了 14%。

这不是 Anthropic 一家的个案。报告里还提到一个细节：面试评价中「是否会使用 AI 工具」这一条被提及的次数，比 2024 年多了近 3 倍（技术岗）到 4 倍（非技术岗）。招聘团队已经把 AI 使用能力纳入了标准化评估维度。

技术部门占全公司的员工比例，也从 61% 降到了 56%。但这里要注意一个常被误读的地方：技术部门绝对人数还在增长，只是增长速度赶不上销售、财务、招聘这些职能部门。报告自己也解释了这一点——公司业务扩张过程中，后端职能的膨胀是自然规律，AI 工具让非技术员工也能独立完成一部分软件工程任务，进一步稀释了纯技术岗的占比。

### 绝对人数仍在增长的原因

公司没有裁员，只是在重新分配每一张桌子上的活儿。

报告的核心数据是：到 2026 年 8 月，员工自己调用的交互式 Claude Agent 累计运行时长，达到了全体员工工作时长的 6 倍。这里的Agent工时只算实际运行和调用工具的时间，不含人类思考和决策的时间。工程师人均代码提交速度在半年内提高了 5.1 倍，数据科学家查询量提高 3.1 倍，法务处理合同数提高 3.1 倍，销售成单量提高 1.7 倍。

产出更多代码并不等同于代码质量更高或是业务收益更好——但报告至今未发现质量下降的迹象。

问题在于，产出增加带来了新的摩擦点。哪怕是非技术员工，要读完自己几个 Claude Agent 全部产出，要花掉半周工时。于是员工开始干一类新活，报告把它命名为「meta-work」——搭看板、盯流水线、管Agent产出的活。

这类工作占员工交互式 Claude 会话的比例，从 10% 上升到了 22%。换句话说，每五个 Claude 使用场景里，就有一个是在管另一个 Claude。

技术部门员工占比从 61% 降到 56%，但绝对数量仍在涨。销售、财务、招聘三部门的招聘增速超过了技术部门。这不是技术岗位在萎缩，而是整家公司的劳动力结构在被重新校准。

更狠的是，这种校准已经在复制。麦肯锡 2026 年公布的内部数据显示，其 6 万员工中约有 2.5 万名是 AI Agent。Anthropic 的报告提供了第一个来自一线科技公司的完整量化证据：当 Agent 进入工作流，最先收缩的不是总人数，而是初级岗位的入口。

## Agent工时为什么已经是人的6倍

这个数据来自 Anthropic 10月16日发布的内部研究报告《How Employment is Changing at Anthropic》。报告基于公司内部的就业记录、AI使用遥测数据、员工产出指标，并结合了17次员工深度访谈。到2026年8月，员工自己调用的交互式Agent累计运行时长达到了全体员工工作时长的6倍。

这里的计算方式很关键：员工工时按每人每周40小时估算，Agent只算实际运行和调用工具的时间。这意味着每一个Claude Agent在工作时都在消耗计算资源和API调用，而不仅仅是「辅助」人类。

### 从写代码到修Bug再到跑测试

工程师人均代码提交速度在半年内提高了5.1倍。但提高的不是写代码的速度，而是整个开发周期的速度。

过去一个功能从需求到上线，需要经过：写代码、自测、Debug、跑测试、提交PR、Code Review、合并。现在Agent可以完成前三个环节——它写代码、跑测试、发现报错、自己修Bug。工程师的介入点后移到了PR阶段，主要是Review Agent的改动是否合理、是否符合业务逻辑。

这解释了为什么初级岗位需求下降。初级工程师的价值在过去很大程度上体现在「能快速完成标准化编码任务」——写CRUD、写单元测试、修小Bug。这些正是Agent现在能替代的部分。而资深工程师的核心价值在于「判断力」——知道什么时候该让Agent自己决策，什么时候必须介入，出了问题怎么排查。这种判断力无法通过写更多代码来体现。

代码质量呢？报告指出，「产出更多代码并不等同于代码质量更高或是业务收益更好——但报告至今未发现质量下降的迹象。」这是个重要边界条件：Agent提升了产出速度，但没有牺牲质量。这得益于Anthropic内部已经建立了Agent产出的审查机制，不是完全放任。

### 非技术岗位同样被重塑

这不是技术团队的专属现象。报告追踪的六类岗位都出现了明显增长：工程师commits 5.1×，数据科学家queries 3.1×，法务处理合同3.1×，销售成单1.7×，招聘入职1.4×，应付发票1.4×。

法务部门的变化尤为典型。过去合同审查是初级律师的核心工作——逐条检查条款、比对模板、标注风险点。现在Agent可以快速完成初筛，律师的介入点变成了「判断Agent标注的风险是否真实」和「处理Agent无法判断的复杂条款」。工作总量没有减少，但工作的性质变了。

销售部门的改变相对温和。Agent可以帮忙整理客户资料、起草跟进邮件、生成提案初稿。但销售的核心能力——理解客户需求、建立信任关系、谈判成交——仍然高度依赖人。所以销售的产出提升幅度（1.7×）远低于工程师（5.1×），因为真正困难的环节无法被Agent替代。

## 人卡在哪里

### 注意力成为新瓶颈

Anthropic 内部有一个让人意外的发现：即使非技术员工，要把自己那几个Claude Agent的全部产出全读一遍，也得花掉半个工作周。

这意味着什么？意味着Agent产生了很多东西，但消化这些东西需要人花大量时间。以前一个人写代码自己debug，现在Agent写了一堆代码，人得逐行Review。以前一个人发二十封邮件，现在Agent帮你写了二十封邮件草稿，你得看一遍再决定要不要发。

人的注意力成了新的稀缺资源。报告引用员工的话说：「Claude 的产出太多，我有时候来不及看。」这不是代码质量问题，是信息过载问题。

### 管理Agent的工作成为新工种

报告把这类工作命名为「meta-work」——管理Agent的工作。具体包括：搭建看板、监控Agent pipeline、搭审查系统、定义Agent的职责边界。

这类工作占员工交互式Claude会话的比例从10%上升到了22%。也就是说，每工作5小时，就有1小时在「管理AI」而非「直接干活」。

这解释了为什么公司还在扩招。一部分新增的岗位不是传统意义上的「执行岗」，而是「Agent管理岗」。这些岗位不需要传统意义上的编码能力，但需要判断力、流程设计能力和跨团队协作能力。这正是报告提到的招聘标准变化的核心：更看重自主性和判断力，相对弱化具体技术领域。

面试评价里提到候选人会不会用AI工具的次数，比2024年多了好几倍——技术岗约3倍，非技术岗约4倍。这说明AI使用能力已经从加分项变成了必选项。

## 公司的取舍逻辑

### 招聘标准的变化

大概三分之一的机器学习经理、五分之一的软件工程经理表示，因为AI招人少了。但这不是「裁掉初级工程师换Agent」这么简单。更准确地说，是「不再通过大量招聘初级工程师来培养人」，而是「直接招有判断力的人，让他们学会用Agent」。

这是一种效率取向的取舍：愿意牺牲人才梯队的厚度，换取当下的产出效率。短期看没问题——每个人都能直接用最高效的工具干活。长期看的风险是：公司里缺乏那些「从基层一步步摸爬滚打上来、对各种问题都见过」的人。这种人过去是靠初级岗位的培养机制练出来的，现在这个机制被削弱了。

### 组织结构的重新设计

技术部门员工占全公司的比例从61%降到56%，不过技术岗的绝对人数还在增长。这说明销售、财务、招聘这些非技术部门招得更快——因为公司规模在扩大，业务复杂度在提升，需要更多的人来协调、沟通、决策。

Anthropic 同时建立了岗位风险预警机制，并优先在内部重新调配受影响员工。这是一种对冲策略：知道哪些岗位会被冲击，提前安排转岗，避免突然裁员带来的组织震荡。

不过这份报告的局限性也很明显：它只记录了Anthropic自己的情况。其他公司的用工变化是否遵循同样的模式？Agent工时的计算方式是否可比？这些问题报告没有回答。但无论如何，这是一个高信噪比的信号——至少说明行业头部公司在认真思考这个问题，而不是等着市场教他们。

## 我们能做什么

对技术从业者来说，答案很直接：学会用Agent，但别指望Agent替你思考。判断力才是你的核心竞争力。具体到行动上，可以今天就做三件事：第一，把你手头最重复的工作列出来，找对应的Agent工具替代；第二，建立一个审查Agent产出的流程，哪怕只是简单的 checklist；第三，主动问自己：我的工作中，哪些是Agent能做的，哪些必须是我想清楚的。

对非技术岗位的人来说，变化也在发生。你的工作效率可能已经提升了，但你还没意识到自己正在承担「meta-work」——管理工具、审查产出、定义边界。这不是额外的负担，而是新岗位的起点。

## 「meta-work」的崛起：人的注意力成为新瓶颈

Agent 产出的体积正在吃掉人的注意力。

报告追踪的数据显示，哪怕是行政、法务、销售等非技术岗位，读完自己那几位 Claude Agent 的产出，平均要耗费半个工作日。一名营销经理说，每天早上第一个小时不是在写方案，而是在「消化 Agent 昨晚跑出来的那一堆东西」。

这意味着什么。Agent 负责生成、填充、跑流程，人负责读、判断、决定走不走。以前一个初级工程师的活，现在是一串 Agent 跑完以后，找个有经验的人过一遍——但过一遍这件事本身，也需要时间。

### 半个工作日读 Agent 的产出

Anthropic 把这种新兴工作类型命名为「meta-work」——围绕 Agent 展开的管理性工作，而不是直接产出代码或文案本身。

具体包括：搭监控看板、审查 Agent 流水线、核对输出结果、维护上下文文档、把 Agent 决策链路的异常标记出来让人工介入。这类工作不会出现在传统 JD 里，但在 Anthropic 内部已经形成了一类隐形岗位。

一名数据科学家在访谈里说，他现在的核心能力已经不是写 SQL 查询，而是「判断哪些 Agent 产出的查询结果需要人工复核，哪些可以直接入库」。

### 审查和监控占总会话的 22%

最直观的量化证据来自交互式 Claude 会话的用途分布。

2025 年初，meta-work 类对话占员工总对话量的 10%。到 2026 年 8 月，这个比例已经升到了 22%。这意味着每五个对话里就有一个是在做「围绕 Agent 的管理」——而不是直接让 Agent 干活。

工作流被拆开成两层。下面是 Agent 在执行，上面是人类在审查。这个「上面」的位置，就是新工作的来源。

## 人的角色转型：从执行者到编排者

这不只是 Anthropic 一家公司的问题，而是 AI 深度嵌入工作流后的结构性变化。

报告里有一个被反复提及的发现：员工的人均会议时长同比上升了 20%，技术岗位的会议时长上涨 16%。公司给出的解释是「人与人的信任和责任感追溯在复杂任务中仍然不可替代」。

换句话说，Agent 能写代码，但不能替你开会解释为什么这么写。Agent 能跑测试，但不能替你在评审会上回答「这个边界情况你怎么处理的」。

### 任务编排成为新核心能力

一名软件工程经理告诉研究者，现在 hiring 一个工程师，最关键的指标已经从「能不能把功能跑通」变成了「能不能判断什么时候该让 Agent 做、什么时候该停下来人工介入」。

这种判断力的培养路径，跟过去完全不同。以前初级工程师通过大量写代码积累经验，现在代码大部分被 Agent 代写了，经验的来源变成了「看过多少 Agent 跑偏的案例，知道在哪里要介入」。

### 面试评价的变化

报告分析了自 2024 年以来技术岗和非技术岗的面试评分卡。

评价里提到「是否会使用 AI 工具」的次数，技术岗同比增加了约 3 倍，非技术岗增加了约 4 倍。一个不会用 AI 的候选人，在 2024 年可能只是「工具熟练度一般」，到了 2026 年已经变成了「不太适合当前工作模式」。

## 招聘标准在变：从写代码到做判断

报告追踪了自 2024 年以来的招聘决策评分卡，发现了一个清晰的趋势：面试评价里提到候选人会不会用 AI 工具的次数，比 2024 年多了好几倍。技术岗约 3 倍，非技术岗约 4 倍。

这不是说「会用 AI」成了一个加分项。而是说，不会用 AI 的人，开始被筛掉了。

与此同时，具体技术领域的权重在下降。三分之一的机器学习经理、五分之一的软件工程经理明确表示，因为 AI 工具的存在，他们招人少了。但他们招的人，要求更高了。

核心差异在于：以前你面试一个初级工程师，看的是他能不能把需求翻译成代码；现在你面试同一个人，要看的是他能不能判断「这个需求该不该让 Agent 去干、干到什么程度、出了什么问题该往哪查」。



![程序员 reaction：柯南00022 你说我在听](https://iili.io/CgJVgwu.png)
> 系统设计题突然变成了Agent编排题



这种转变在面试环节就已经开始显影。候选人如果只会写代码、不会分配任务，大概率会被刷。候选人如果知道什么时候该信任 Agent 的产出、什么时候该怀疑，反而能拿到 offer。

报告里有一个细节值得玩味：有员工换了工作职责之后，Agent 还是会不断来问他 T 恤、杯子这类公司周边的问题，因为旧文档里的负责人字段没有跟着更新。

这个例子说明了一件事：人的角色已经转型，但组织记忆还在用旧模板。

## 这份报告为什么值得全行业关注

Anthropic 不是第一个把 AI 深度嵌入工作流的公司，但它是第一个把数据公开到这种程度的。

麦肯锡宣布拥有 2.5 万名智能体员工的消息传出后，行业里出现了一种误解：以为这是裁员的前兆。实际上，麦肯锡的 2.5 万「员工」里，真正在跑任务的 Agent 只有部分，更多是闲置或探索性部署。Anthropic 的数据更接近真实运转状态——Agent 工时已经是人类的 6 倍，且这个数字还在涨。

更准确地说，Anthropic 揭示的是一个结构性信号：初级岗位正在被重新定义，而不是被消灭。

报告里还提到一个有趣的对比：Anthropic 员工估计四年后 AI 能完成自己 75% 的工作，而普通美国公众只估 28%。这两组的差距，主要来自每天用 AI 的亲身体验不同。

这意味着什么？意味着行业里对 AI 影响的认知，已经出现了明显的断层。用得多的人，知道 AI 能干多少；用得少的人，还在用传统框架估算。

初级岗位的收缩，是这种断层在招聘市场里的直接映射。

## 给从业者和公司的可执行判断

对求职者来说，结论很直接：如果你的核心能力还停留在「写代码」「做表」「翻译需求」，那你的价值正在被快速稀释。不是说你找不到工作，而是说你找到的工作，很可能不是你想做的那种。

提升判断力和自主性，是当下最值得投资的能力。具体来说，可以做的三件事：

第一，在你的工作流里植入 Agent，至少让一个重复性任务被自动化，然后观察它哪里做得好、哪里会出错。第二，学会写清晰的指令——什么事 Agent 可以自己决定，什么情况必须来问你，哪些结果需要先检查再交付。第三，培养审查习惯，不信任第一次产出，但不排斥迭代后的产出。

对公司来说，报告给出了一个明确的取舍：短期看，用 AI 工具提升人效是确定的；长期看，初级岗位的培养机制需要重建。以前的「初级工程师干杂活、 senior 工程师做架构」的模式，正在失效。

Anthropic 的做法是建立岗位风险预警系统，优先在内部重新调配受影响员工。这比直接裁掉更有意义——你的 AI 策略越强，员工流失成本越高。

边界在哪里？报告承认，「产出更多代码并不等同于代码质量更高或是业务收益更好」。目前尚未发现代码质量下降的迹象，但这个结论有时间窗口。当 Agent 承担的任务复杂度继续上升，质量监控的成本也会同步上升。

更狠的是，每年能省下一个亿的同时，你还得养一支专门盯 Agent 的「meta-work」团队。这不是免费的效率提升，这是一次用工结构的深度重组。

取舍的结论很清楚：在 AI 工具已经成熟且团队有足够判断力监督产出的前提下，优先投资高级人才的判断力培养；当团队还停留在「让 Agent 干活、人看结果」的阶段时，别急着扩招，先把审查机制搭起来。
