## 一、工具出现：从 VideoTutor 失效说起

### 1.1 一条读者反馈引发的替代搜索

前几天有读者在公众号留言：VideoTutor 进不去了，页面变成「提交简历」界面。我点开确认了一下，确实如此。

这个结果不算意外。VideoTutor 上线不久就经历了多次访问限制，社区里关于「还能用吗」「有没有平替」的讨论一直很密集。

于是顺藤找了一圈。答案指向两个方向：一个是雾象（fogsight.ai），一个是 GitHub 上的 Anatomy Skill。

### 1.2 Anatomy 是什么：一句话定义

Anatomy 是一个 Claude Code Skill，作用是把任意抽象概念翻译成可交互的机械模型动画。

它不生成真人出镜视频，也不生成写实风格画面。它的产出是：一组 HTML + CSS + JS 组成的可交互装置图，带标注、可点击、可拖动滑块调整参数。



![程序员系列表情：他说你 app 一点就崩](https://iili.io/CsnC2LB.png)

![Anatomy 工作流概览](https://iili.io/njfl09j.png)

和 VideoTutor 的核心差异在于输出形态：VideoTutor 产出的是线性播放的视频文件，Anatomy 产出的是一个可以在浏览器里直接跑的交互式页面。这意味着你输入同一个问题两次，每次得到的装置结构和参数映射可能不同——它是在现场构造，而不只是检索模板。

我上周做了实测，用三个不同领域的主题跑了一遍：光合作用、贾宝玉人物性格、算法可视化。结果有些超出预期，也有些明显局限。下面逐条记录。

## 二、实测过程：我用了三个主题跑了一遍

### 2.1 理科主题：光合作用原理动画

提示词很简单：「讲解光合作用的原理，适合初中生」。

不到两分钟，生成了一段完整的动画视频。内容结构清晰：先给结论（植物将光能转化为化学能），再展开过程（叶绿体、二氧化碳、水、阳光），最后落到产物（氧气和葡萄糖）。动画展示叶子的过程，水从根部上升、二氧化碳从气孔进入，阳光照射后的能量转换用动态箭头标注。配音语气平稳，节奏适中，结尾还带了一个练习题。

精度方面，核心机制没有错误，画面也干净。问题在于，这更像是把教科书原文做了个动画化，而不是真正的「可视化」。比如光反应和暗反应两个阶段的关系，没有交叉对比，只是线性叙述。

对于初中生的入门场景，够用。但如果要讲解 C4 植物的特殊机制，这个粒度就不够了。

### 2.2 人文主题：贾宝玉人物性格分析

这是一个更有挑战性的测试，因为人文内容很难用机械模型来表现。

提示词：「分析《红楼梦》中贾宝玉的人物性格」。

生成结果是几个关键词加人物图像：「重情」「叛逆」「厌恶仕途」「平等对待女性」。配音温和，节奏平缓，结尾留了一个开放式问题。

这个场景暴露了 Anatomy 的能力边界。它能做关键词罗列和图像搭配，但没有办法做深度论证——比如宝玉对女性的态度与其他角色的对比，或者叛逆性格的社会根源。这些需要文本推理和结构化表达，不是机械动画能承载的。

它更像是一个视觉辅助工具，不是分析引擎。

### 2.3 技术主题：算法可视化演示

第三个测试是技术类。提示词：「可视化演示快速排序算法」。

这个场景的期待最高，因为算法本身就是机械性的——步骤清晰、逻辑明确、可以用动画逐帧展示。

结果确实不错。动画用两个指针的移动来演示分区过程，数值交换有过渡动画，递归调用用层级缩进表示。整体观感接近专业的教学视频。

但有一个细节值得注意：生成的动画是预设模板式的，不是真正实时运行的代码。你看到的是预渲染的演示路径，而不是算法的动态执行过程。这意味着如果输入不同的数据分布（比如已排序数组），动画不会改变，依然是同一个模板。

对于教学演示，这已经足够。但对于需要理解算法在不同输入下的行为差异的场景，局限性很明显。

---

三次实测下来，能得出一个基本判断：Anatomy 适合「概念可视化」，不适合「深度论证」。它的强项是把抽象概念翻译成可交互的机械模型，弱项是处理需要结构化推理或复杂对比的内容。

## 三、机制拆解：它到底在做什么

Anatomy 的本质是一个 Claude Code Skill，它的核心逻辑是三步：找类比、建模型、出动画。

第一步，找到现实中的机械装置来类比抽象概念。缓存机制对应水管阀门，快速排序对应分治切分，光合作用对应工厂流水线。这个类比的质量决定了最终动画的可读性。

第二步，用 Remotion 生成可交互的机械动画。Remotion 是一个基于 React 的视频合成框架，支持程序化生成动画，每个元素都可以用代码控制位置和状态。

第三步，配上语音讲解和字幕，输出一段完整的视频。



![Anatomy Skill 工作流](https://iili.io/njflLHG.png)

这个流程的关键瓶颈在第一步。类比的质量完全依赖 LLM 的理解和联想能力，如果概念本身比较抽象或者找不到合适的机械装置，生成的动画就会显得牵强。

## 四、取舍与边界

### 4.1 适合的场景

需要动画演示的概念有几个特征：第一，有明确的机械或物理结构可以类比；第二，过程是分步骤的，可以被逐帧展示；第三，目标是入门级理解，不需要深入机制细节。

符合这些条件的典型场景包括：初中理科教学、科普短视频、技术概念入门讲解。

### 4.2 不适合的场景

不适合的场景也很明确：需要深度论证的人文话题、需要真实数据驱动的可视化、需要动态响应的交互式演示。

另外，当前版本的输出是预渲染的静态动画，无法根据输入数据动态调整。这意味着它适合「讲清楚一个机制」，不适合「演示一组数据的演变」。

### 4.3 与 VideoTutor 的对比

VideoTutor 的问题在于入口卡住了——需要提交简历才能创建。Anatomy 是开源的，本地部署或在线使用都可以，门槛更低。

但两者定位略有不同：VideoTutor 更偏向教学类科普，Anatomy 更偏向概念可视化。如果你需要一个完全自动化的视频生产线，两者都不够，还需要配合其他工具做后期处理和分发。

### 4.4 一句话判断

在「需要把抽象概念做成入门级动画视频」这个条件下，Anatomy 是目前开源圈里最值得尝试的方案。它的产出质量稳定，工作流简单，成本几乎为零。

超出这个条件，比如需要做数据分析可视化、或需要深度论证的视频，还是得回到传统工作流。

更狠的是，每年能省下一个亿——前提是你们团队都在做概念动画这种场景。

## 五、开源项目的获取与后续

### 5.1 GitHub 地址和部署方式

Anatomy 的 GitHub 仓库是公开的，可以直接克隆到本地使用。

本地部署的基本步骤：

第一，安装 Claude Code。这是前提条件，需要有一个 Anthropic API Key。
第二，克隆 Anatomy 仓库。用 git clone 命令将项目拉到本地。
第三，配置 Skill。按照仓库的 README 说明，将 Skill 文件放置到正确位置。
第四，启动测试。用 Claude Code 调用 Skill，输入测试提示词验证效果。

仓库地址和详细部署说明可以在 GitHub 上找到。对于不熟悉命令行操作的用户，建议先使用在线版本体验，再决定是否本地部署。

### 5.3 对内容创作者工作流的实际影响

Anatomy 这类工具的出现，正在改变内容创作的工作流。

传统的动画视频制作流程是：写稿 → 设计分镜 → 制作动画 → 配音 → 剪辑合成。这个流程需要多人协作，耗时数天甚至数周。

Anatomy 把前四个环节压缩成了一个：写提示词 → 生成视频。剩下的剪辑合成如果需要，可以用 Remotion 自己微调。

这种效率提升不是线性的，是指数级的。原来需要 3 小时写稿、2 天做动画的内容，现在 1 句话就能搞定。对于知识博主、教育工作者来说，这意味着内容生产力的质的飞跃。

当然，工具不能完全替代人的判断。生成的内容需要审核，动画的逻辑需要校验，配音的语气可能需要调整。这些人工介入的环节，决定了最终内容的质量上限。

坦白讲，Anatomy 目前适合做"草稿"，不适合直接当"成品"。但它已经把最耗时的部分自动化了，剩下的人工打磨时间大大缩短。

**判断落点**：如果你是教师、知识博主、技术写作者，需要频繁生产科普类动画内容，Anatomy 值得试用。本地部署版本适合对数据安全有要求的场景；在线版本适合快速体验。如果你的需求是品牌商业视频或高定制化内容，建议先用 Remotion 自己写代码，Anatomy 只能作为灵感参考。
