给电视去掉广告后，有人花了一个半小时就做到了。

印度开发者 Gathin 在 X 平台分享了自己的经历：一句提示词喂给 Claude Code，调整两项权限、开启 USB 调试模式，再通过同 Wi-Fi 网络发送指令，最终重做了电视界面——去掉了开机广告、简化了操作菜单、把 PlayStation 输入口设成了快捷选项。帖子发出后迅速扩散，他把成果开源为 CleanYourTV（原名 tv-vibehack，19 日更名），成为 GitHub 上最热门的仓库之一，收到数千个 PR 和功能建议。

这不是孤例。The Verge 记者 David Pierce 在周报 The Stepback 中将这类现象称为「vibe coding」——非工程师通过自然语言提示词，让 Claude Code、Codex 等工具生成可直接运行的代码。Karpathy 创造了「vibe coding」这个词，并在 2025 年底的评论里把它推到「个人软件革命」的高度。

## 一、电视改装潮从一句提示开始

Gathin 的 90 分钟可以拆成四步：提示 Claude Code 调整电视上的两项权限；开启 USB 调试模式；电视和聊天代理同处一个 Wi-Fi 网络，互相发送指令；代理按他的偏好重做界面。整个过程没有拆机，没有 root，只有一个 chatbot 和一张沙发。

体验在 X 上爆火之后，Gathin 又做了三件事：买了域名，把完整提示词链开源为 CleanYourTV，然后持续改造这个工具。他的负责任做法值得单独写出来。他分享的提示词默认先备份电视软件，出问题时能直接恢复；沿途记录每一处改动；系统还会中途检查自己的进度，拉起代理做手动测试，确认没有东西坏掉。用他自己的话说，他正在让这套流程「越来越傻瓜化」。

## 二、去广告走的是开发者通道

目前主流的电视改装项目——CleanYourTV、tv-detox、dumbtv——都走同一条路：利用 Android/Google TV 的开发者模式，通过 ADB（Android Debug Bridge）安装或卸载应用包，去掉赞助广告，精简系统让电视跑得更快，同时拦截追踪你看了什么的采集。默认动作是把电视内置的应用 launcher 换成更简单的版本。

关键特征是免 root、免刷机。支持的设备包括 TCL、Hisense、Sony 的部分型号，以及旧款 Amazon Fire TV；Fire TV 的定制分叉部分可用，新款 Vega 芯片的 Fire TV Stick 不在支持列表里。因为它们用的是厂商内置的开发者工具，过程可逆——恢复出厂设置或者卸载自研 launcher，系统就能回到原始状态。



![去广告项目的取舍](https://iili.io/oKt4rN9.png)
> 去广告项目的取舍



部分用户再往前一步：让 AI 生成自己的 launcher。CleanYourTV 仓库里有用户提交的宝可梦主题界面，代码由 Claude Code 一次性生成，没有手写一行 XML。但可逆不等于无风险：ADB 改装依赖的是制造商留下的调试通道，切断广告的同时，也可能触发系统行为异常。有人用同样的方式折腾三星电视，直接变砖。

## 三、风险比广告更值得写进清单

变砖案例是第一道墙：改装的空间集中在 Android/Google TV 阵营，非 Android 阵营基本不在这些项目的支持范围里，失败的代价随之变大。而真正完全避开 ACR、广告和数据收集的办法只有一个：永不联网。但这和智能电视「必须联网才能用」的设计逻辑正面冲突，等于把设备退回盒子阶段。

更现实的替代路径有两条。一条是用 U 盘手动刷固件更新，绕开 Wi-Fi 或网线的自动更新通道；另一条是直接换设备——上一代 Apple TV 4K 没有 ACR 数据收集，界面干净，改装风险可预期。当然，任何流媒体服务都要你先交出一些数据才能跑起来。

The Verge 的专栏同时指出，厂商一方正在回击：更强的 DRM 锁，加上潜在的法律手段，反制 vibe coding 带来的开放化趋势。作者给读者的建议很直白：只在可承受损失的设备上试，并且勤做备份。

## 四、个人软件的安全要提前问

The Verge 的安全专栏给 vibe coding 起了个新名字：「个人软件时代」。任何人都能用 AI 做只属于自己的应用，但应用好做，防护难做——尤其在一个 AI 也能被用来攻击应用的年代。

工具侧的安全能力并不匹配 casual 构建者。OpenAI 的 Codex 内置了安全代理，逐 commit 扫描并复查它自己提的补丁，但它面向的是有真实版本控制工作流的开发者，不是靠聊天把应用聊出来的人。Claude Code 的 /security-review 命令要手动调用；自动版本只有在预先设置好对 pull request 运行时才生效，而大多数 casual 构建者根本没做这层设置。一次普通的 vibe coding 会话里，除非你装了会停下来检查的东西，否则没有任何东西会停下来检查——而大多数人没有装。

SentinelOne 的高级 AI 研究科学家 Gabriel Bernadett-Shapiro 的说法是：vibe coding 的问题不在于业余人士也能做软件，那恰恰是好的部分。真正要记住的是两条：动手前就把安全写进提示词，收尾时再查一遍；「很多安全是情境化的」，代理不理解你的威胁模型时，它自己的审查只会给你虚假的安全感。

## 五、下一波硬件有自己的节奏

软件侧的数字已经在动。The Information 报道，App Store 新应用总量 2025 年增长了 30%，结束了近十年的缓慢下滑；按 Apple 自己的计数，2024 年底应用总数刚不到 200 万，到 2026 年底这个数字可能翻倍。GitHub 在 2025 年经历了史上最快的一年增长，80% 的新用户在第一周就会用上 Copilot 编码代理。

Vergecast 做过一个小对照实验：三位 Verge 记者花一个月，用 vibe coding 工具做解决真实问题的网站。Pierce 每月付 20 美元用 Claude Code，说他对成果「非理性地骄傲」；Kastrenakes 换到 Codex，这个工具在八天里七次罢工且不了解自己的能力，他称这个月「糟糕透顶」；Field 没有付费账户，免费层 Claude 秒被用完、Codex 又被付费墙挡住，最后用九个小时的 Gemini 免费对话做出了一个真实发布的作品集网站，成本为零。结论一致：工具选择和任务设计，比用户技能更决定结果。应用整体能在几分钟内搭好，而一个按钮的样式可能要磨九个小时；产品逻辑活下来了，视觉品味塌了。

给工具定边界的人也不缺。Cherny，Claude Code 的作者，说 vibe coding 适合一次性代码和原型，适合「不在关键路径上」的代码；他判断产品会火，是因为发现销售团队自己都在用。

## 六、可执行的三条底线

一、先备份。CleanYourTV 分享的提示词默认先备份电视软件，出问题时能直接恢复——这是唯一在变砖后还有效的兜底动作。

二、记录改动并自检。把代理做的每一处改动记下来，中途拉起代理做手动验证；出问题时能精确定位回滚点。

三、只在可承受损失的设备上动手。电视可以试，相机、路由器和还在保修期内的设备，先备份、再评估，最后才下提示词。
