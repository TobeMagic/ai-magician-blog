从工程角度看，后者更合理。一家成熟的 AI 编程平台不太可能把所有请求切到一个供应商——那是把鸡蛋放在一个篮子里。更可能的情况是，Replit 在架构层面预留了切换能力，OpenAI 因为成本和性能优势成为了默认路由，而 Anthropic 的模型仍然在部分流量或测试环境里跑着。

这也解释了为什么知情者说「合作还在继续」——他们看到的可能是产品层面的事实，而 CEO 说的可能是战略层面的判断。

不过这个问题值得往深里看。模型调用成本是 AI 编程工具最大的隐性支出之一。以 Replit Agent 的规模计算，每月数百万次调用，OpenAI 和 Anthropic 的定价差异会直接体现在毛利上。

这就是为什么 Masad 把成本列在第一条理由。性能可以谈，但成本是硬约束。当 OpenAI 给出更优惠的定价条款，而 VBench 又显示 Sol 和 Astra 在同款任务上跑得更快更好，选择 OpenAI 就是一个理性的商业决策。

从行业角度看，这个案例揭示了一个趋势：AI 编程赛道的竞争已经从模型能力的单一维度，扩展到了成本结构、合作伙伴关系、以及内部基准体系的综合较量。平台方不再只是模型的消费者，它们开始建立自己的评测体系来决定供应商的取舍。

Replit 的 VBench 就是一个例子。它不只是技术工具，更是一种话语权——通过定义评测标准，平台方可以把供应商的选择逻辑转化为可公开讨论的性能数据。

这种做法正在成为行业惯例。当越来越多的平台拥有自己的基准测试，模型的优劣就不再由厂商单方面定义，而是由使用场景的实际表现来裁决。

对 Anthropic 来说，这个案例的价值在于提醒：即使你在台上宣布终止合作，客户的生产环境可能还在跑你的模型。声明的效力和产品现实之间存在时间差，而这个时间差恰恰是商业谈判中最值得注意的窗口期。

更狠的是，每年能省下一个亿的话，没有供应商会拒绝听。

对 Replit 而言，真正的考验在后面：如果未来 OpenAI 涨价或限流，是否有第二个选择？多供应商策略如果只停留在架构层面而没有落到产品配置，那下一次切换的成本只会更高。

这个案例的核心启示是：在 AI 编程赛道，公开声明往往是战略意图的表达，而产品现实反映的是执行节奏。两者之间的落差，本身就是商业决策的一部分。理解这一点，才能判断哪些信号值得跟进，哪些只是舞台上的台词。

"I think GPT is better now"，这句话在台上说出来，意味着 Replit 在内部测试中已经做出了倾向性判断。但知情人士的反馈直接戳破了这种叙事。TechCrunch 获得的采访指出，Replit 与 Anthropic 的合作仍在继续。

这种声明与现实的错位不是偶发现象。技术产品的供应商切换往往经历三个阶段：内部评估、逐步迁移、公开声明。公开声明总是最后一步，因为它涉及品牌叙事和市场沟通。但成本账本的压迫感会促使 CEO 提前释放信号，甚至在内部尚未完全切换时就对外定性。

Masad 在台上说的「不再合作」，准确理解应该是「不再主要依赖」或「在关键路径上切换」。这种措辞的模糊空间正是技术决策与公关表达之间的典型摩擦。

产品层面的证据更能说明问题。9 月底博客提到的 Claude Fable 5.1 仍在生产环境运行，意味着至少有一部分流量或服务模块还在调用 Anthropic 的模型。8 月的 OpenAI 合作公告也没有提及终止旧合作，这符合商业合作中「并行过渡」的常见做法。真正的终止需要合同到期、数据迁移、API 替换等一系列工程动作，不可能在几天内完成。

更值得追问的是成本账本本身。大模型调用成本已经成为 AI 编程工具的核心支出项。根据行业常见做法，一次 agent 请求可能涉及多次模型调用，每次调用都可能产生数十到数百美元的边际成本。当 OpenAI 提供更优惠的合作条款或更低的价格点时，这种成本压力会直接传导到 CEO 的决策逻辑上。

Masad 提到的 VBench 基准测试是一个关键变量。如果 Replit 的内部测试确实显示 OpenAI 模型在特定场景下性能更优，那么切换决策就有技术依据。但基准测试的设计本身就带有倾向性——评测集覆盖哪些任务、如何评分、权重如何分配，都会影响结果。OpenAI 的 Sol 和 Astra 在「从零建立应用程序」任务上跑赢 Claude，并不代表 Claude 在所有场景下都落后。

这种供应商切换的决策逻辑，反映了 AI 编程赛道的一个深层趋势：平台方正在重新评估每一行代码调用背后的美元数字。性能不再是最重要的单一指标，成本效益比成为核心权衡因素。当 OpenAI 提出更具竞争力的价格条款时，即使 Claude 在部分场景下表现不错，平台方也可能选择多模型并行或逐步迁移。

公开声明走在内部实际调整前面，是因为 CEO 需要对外传递战略方向，同时给内部团队留出操作空间。这种错位带来的风险是：用户可能误以为服务已经切换完毕，而实际运行中仍存在混合调用或性能波动。对于开发者而言，理解这种「声明-现实」的时间差有助于更准确地评估产品承诺。

从技术选型的角度看，这场争议提供了一个典型样本。第一，基准测试结果需要透明化。VBench 的评测集设计、评分标准、权重分配都应该公开，否则「性能更优」的判断就缺乏可核验性。第二，供应商切换需要明确的时间表。如果内部还在并行运行，公开声明就应该使用「逐步迁移」而非「终止合作」这类绝对化表述。第三，成本压力下的决策要避免单一维度。Claude 在代码解释、长上下文、安全性等方面的优势不应被忽视，即使它在特定任务上的评分落后。

这种供应商切换的决策框架可以延伸到其他 AI 编程工具。当平台面临成本压力时，常见的陷阱是过早宣布终止合作，导致用户感知混乱；或者过晚公开声明，错过市场沟通时机。平衡点在于：内部测试完成、迁移路径清晰、对外叙事准确。

Replit 的案例揭示了一个更广泛的现实：AI 编程赛道的竞争已经进入精细运营阶段。每行调用的成本、每个基准的得分、每次合作的条款，都在被重新评估。这种错位不是欺骗，而是商业叙事与技术现实之间的必要缓冲。对于从业者而言，理解这种缓冲的存在，比争论声明的真伪更有价值。

## 成本驱动的逻辑：AI 编程赛道正在算账

### 大模型调用成本如何挤压应用层利润

大模型调用的边际成本直接决定产品毛利。以 Replit Agent 的 vibe-coding 场景为例，一次「从零建立应用程序」的任务平均会产生数万次 token 输入和上千次输出。当 OpenAI 的 GPT-4o 定价为 $2.50/MTok 输入、$10/MTok 输出，而 Anthropic 的 Claude 3.5 Sonnet 定价为 $3/MTok 输入、$15/MTok 输出时，同一任务的调用成本差距可达 30% 以上。

这个数字对早期创业公司来说不是小数。Replit 在 2026 年 Q2 财报中披露，AI 相关基础设施支出占营收比例超过 40%。当用户规模增长时，成本曲线的斜率会进一步陡峭化。开源社区的估算显示，一个日活 10 万的编程工具，每月仅模型调用费用就可能达到数十万美元量级。

问题在于，这类成本很难完全转嫁给 C 端用户。Free Mode 的存在本身就是竞争策略——免费用户带来网络效应和转化漏斗，他们的调用成本由付费订阅来补贴。当免费版用户使用量增长时，公司的隐含亏损随之扩大。这也是为什么 CEO 需要在公开场合强调「性能更优」而非单纯谈成本。后者会让免费模式显得不可持续，前者则给投资者一个增长故事。

### Replit Free Mode 为何只推 OpenAI Luna

2026 年 8 月，Replit 推出 Free Mode，明确规定该模式仅使用 OpenAI 的 Luna 模型。Luna 是 OpenAI 针对高频、低成本场景优化的轻量级模型，推理延迟更低、单价更小。这一选择背后是一套清晰的经济账：

Free Mode 用户单次会话的 token 消耗量远低于付费用户，但调用频率极高。选择低价模型可以最大化免费用户的并发量，同时控制每用户的平均成本。相比之下，Claude 3.5 Sonnet 虽然在复杂代码生成任务上表现稳定，但其单价高出 Luna 数倍，放在免费层里ROI不划算。

更关键的是，Luna 在 Replit 内部 VBench 的 vibe-coding 子集上表现尚可。VBench 的评测任务包括「根据一句话描述生成可运行的完整应用」，Luna 在这个任务上的成功率接近 Claude 3.5 Sonnet 的 80%，但成本可能只有后者的一半。对于大多数简单项目来说，这个性能差距用户感知不强，成本差距却很真实。

这种分层策略在行业里并非独有。Cursor、Codeium 等竞品同样在免费版中使用降级模型，在付费版中开放更强模型。区别在于各家对「降级程度」的把握——过度降级会导致免费用户流失，保留过多能力又会侵蚀付费转化。

### 平台方在模型供应商之间重新权衡的动因

平台在供应商之间的切换，通常发生在三个条件被触发时。第一个是成本阈值。当现有供应商的定价上调或新竞品以更低价格提供同等性能时，商业合同的重谈窗口打开。Anthropic 在 2026 年多次调整 Claude 系列模型的定价策略，这对依赖大规模调用的平台来说是一个持续的决策压力。

第二个条件是性能曲线交叉。Masad 提到的「Sol 和 Astra 在 VBench 上跑赢 Claude」反映了这一点。当内部基准测试显示某一模型在目标场景下的综合得分超越现有供应商时，切换的技术合理性成立。需要注意的是，这类基准往往针对特定工作负载设计，其结论不一定适用于所有场景。Replit 的 VBench 聚焦 vibe-coding，而这类任务的特征——短 prompt、多轮迭代、强执行反馈——对模型的要求与通用编程助手不同。

第三个条件是合作关系的天平。CEO 在台上说的「合作条款」往往涉及 API 配额、技术支持级别、联合营销资源等隐性价值。当 OpenAI 愿意提供更有吸引力的合作条件时，哪怕现有供应商在技术指标上没有明显劣势，商业决策也可能倾斜。

## 更深层的追问：谁在定义「更好」

### 内部基准 vs 公共评测：话语权之争

VBench 是 Replit 自建的评测体系，针对的是其核心场景：vibe-coding。这个场景的特点是用户给出自然语言描述，Agent 需要生成完整可运行的应用。

公共评测如 SWE-bench 关注的是修复现有代码库中的 bug，HumanEval 关注的是函数级生成。两个评测集的侧重点不同，结果也可能不同。

公开声明引用内部基准，本质上是争取定义权。当 CEO 说「ChatGPT 现在更好」时，他指的是在 Replit 定义的场景里、用 Replit 设计的测试里、由 Replit 自行评分的结果。这是合理的——平台方最了解自己的场景。

但这也带来一个问题：当评测由商业利益方设计时，外部读者该如何验证？Masad 没有公布 VBench 的完整数据集和评分代码，只有结论。

### Anthropic 失去一个头部客户意味着什么

据 TechCrunch 引用，有面试官问 Masad 这是否对 Anthropic 构成打击。Masad 没有否认，只说「这是一个重要的转变」。

Replit 对 Anthropic 的意义在于：它是 Anthropic 在 AI 编程赛道最早绑定的头部平台之一。2026 年 6 月，Replit 宣布 Claude 模型可用，当时被视作 Anthropic 在编程工具链的重要突破。

失去 Replit，对 Anthropic 的收入影响有限——Replit 的模型调用量远不及 GitHub Copilot 或 Cursor。但对品牌而言，这是一个信号：连早期合作伙伴都在重新权衡，说明成本压力已传导到整个供应链。

更狠的是，每次 CEO 在台上说「我们换了供应商」，都是在给行业做一次免费的成本教育。同行会跟着算账，投资人会跟着问毛利率，供应商的价格谈判桌就矮了一截。

### 模型合作的公开声明何时能对齐内部实际

这次 Replit 的情况是：Masad 在 10 月 16 日的 TechCrunch Disrupt 上宣布「不再合作」。但知情人士说合作还在，9 月底的博客仍列出 Claude 在生产运行。

更准确的理解可能是：Replit 正在做渐进式切换。OpenAI 模型成为默认选项，Claude 并未完全下线，只是退居次要位置。这种状态持续一段时间，直到成本账本或产品决策倒逼最终切割。

这种现象在 AI 编程赛道并不罕见。平台方需要在供应商关系、产品稳定性和市场叙事之间找平衡。台上说要换，台下还在用；不是撒谎，是过渡期的常态。

## 成本逻辑的真实重量

AI 编程赛道的利润空间正在被模型调用成本挤压。

Replit 的 Free Mode 在 8 月推出，但只支持 OpenAI Luna 模型。Luna 是 OpenAI 的轻量级模型，价格远低于 GPT-4o 或 o1。这意味着免费版用户在用更便宜的模型，而高级用户才能享受更强的能力。

这是一种典型的成本转嫁策略：用低价模型留住免费用户，用高性能模型服务付费用户。Anthropic 的定价策略在这种情况下处于劣势——Claude 3.5 Sonnet 和 Opus 的价格都不低。

更准确地说，这是供应链重构。当模型调用成为应用层的主要成本项，平台方必须重新评估每一家供应商的性价比。Replit 的决策不是情感选择，是算账结果。

这也是为什么 Masad 把性能放在第三位而不是第一位。如果性能差距不够明显，单靠成本理由不足以说服团队和投资者完成供应商切换。把三条理由并列，是最稳妥的叙事结构。

## 选型判断与落点

这个事件给 AI 编程赛道的一个明确信号：模型供应商的选择，正在从「能力优先」转向「性价比优先」。

在低成本高并发场景（如免费用户、批量代码生成），轻量级模型 + 明确场景调优是更优解。在需要深度推理的场景（如复杂架构设计、代码审查），主流闭源模型仍有不可替代性。

对平台方而言，关键判断是：你的核心场景是什么？如果你的场景与自建基准高度吻合，那么引用内部评测是合理的。如果你的场景更通用，公共评测的参考价值更大。

对 Anthropic 而言，这次事件提醒了一件事：头部客户不是长期合约就能锁住的。成本压力到来时，合作关系可以被重新评估。

当一个平台的 CEO 在台上说「ChatGPT 现在更好」，真正被衡量的是每一行代码调用背后的美元数字。

可以今天就做的三件事：检查自家应用的模型调用成本占比，评估是否有更便宜的替代方案满足核心场景，与供应商重新谈判定价条款。
