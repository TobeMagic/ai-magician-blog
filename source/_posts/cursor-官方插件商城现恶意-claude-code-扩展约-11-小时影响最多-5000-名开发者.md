你从官方插件商城装下一个看起来一切正常的 Claude Code 扩展。

## 事件回放：官方商城里的 11 小时

太平洋时间 10 月 29 日凌晨 2:27，版本号为 2.1.313 的 Claude Code 扩展出现在 Cursor Marketplace。下午 1:35，它被下架，前后在线约 11 小时。

这不是 Anthropic 发布的包。 Cursor 确认了这一点，并指出最多约 5000 名开发者在这 11 小时内下载并安装了该扩展。



![程序员反应图：真正的程序员](https://iili.io/CUyhliQ.png)
> 装扩展的时候谁没想过"这是官方商城，应该没问题"



Cursor 随后关闭了商城进行安全审计，逐个联系受影响用户，并推送了 2.1.314 版本要求用户更新。

攻击者的切入点很直接：改了一个文件，在正常代码前插入了 66 行 JavaScript。原有功能代码几乎没动，扩展看起来照常工作。但 Cursor 只要加载这个扩展，那 66 行恶意代码就会执行，不需要用户主动打开 Claude Code。

## 恶意代码做了什么

安全研究人员拆解了这段 66 行的恶意加载器，它的动作可以归纳为四类。

第一类是信息收集。它获取主机名、用户名、操作系统、架构、home 路径、环境变量名（注意是变量名，不是值）、工作目录、Git 邮箱和公网 IP。这些信息被打包发送到攻击者控制的服务器。

第二类是 SSH 后门植入。恶意代码向 ~/.ssh/authorized_keys 追加一个带有 `svc-telemetry` 标记的公钥。这个标记很讲究——它看起来像遥测服务，不像攻击者的钥匙。攻击者借此获得无需密码即可 SSH 登录的能力。

第三类是尝试建立反向隧道。即使 SSH 远程登录因权限问题失败（多数 macOS 和 Windows 电脑默认不开 SSH 服务，且需要管理员权限），恶意代码仍然会尝试连接攻击者的服务器。

第四类是持久化。它在 macOS 和 Windows 上分别安装了后台脚本，设置为开机自启，每隔约 60 秒尝试重新连接。

![程序员 reaction：柯南00068 哼](https://iili.io/nOeBaDX.png)

这里有一个关键细节：攻击者的代码存在错误。大多数情况下，启用 SSH 远程登录这一步会失败——因为它需要管理员权限，而扩展通常以普通用户身份运行。但即使登录失败，信息收集和持久化脚本的安装可能已经完成了。

真正危险的不是"能不能远程连上"，而是"你的 SSH 配置里有没有多出一把陌生钥匙"。

## 供应链攻击为何选官方商城

这个事件最让人不舒服的地方，不在于攻击技术本身有多高超，而在于攻击者选择了什么路径。

官方插件商城的审核门槛天然比第三方渠道低。用户看到「Claude Code」这个名字、看到它在 Cursor Marketplace 里，第一反应是信任。攻击者不需要伪造签名、不需要绕过网关、不需要社会工程学诱导——只需要让包进入审核通过的队列。

Claude Code 本身也是一个精准选择。它是 Anthropic 推出的终端原生 AI 编程工具，热度高、用户群体集中（开发者），且通过 VS Code 扩展接口运行。这意味着安装它的人，大概率已经有 SSH 密钥、Git 凭据和远程服务器访问权限。拿到一把能 SSH 登录的钥匙，比拿到一堆日志有价值得多。



![程序员 reaction：你被我盯上了](https://iili.io/CCZOwMJ.png)
> 官方商城这个名字，就是最大的信任杠杆



Cursor 的安全公告没有说明攻击者是如何把包放进商城的。审计访问记录、轮换密钥、重建市场——这几步操作暗示发布链路或内部凭据出了问题。具体是哪一个，还需要等官方后续说明。

供应链攻击的演变趋势很清楚：以前是攻组件仓库（如 npm、PyPI），现在是攻IDE 的插件商城。用户对这些渠道的信任更直接，审核机制往往跟不上发布速度，而一旦被采纳，影响力是即时的、批量级的。

## 自查与修复清单

如果你在这 11 小时内安装了 Claude Code 2.1.313，以下是现在就能做的动作。

第一步：更新扩展。将 Claude Code 扩展升级到 2.1.314 或更高版本。这是 Cursor 官方推出的修复版本。

第二步：检查 SSH 密钥。运行以下命令检查是否有非预期的公钥：

grep -i "svc-telemetry" ~/.ssh/authorized_keys

如果有输出，说明你的机器已经被植入。删除那行密钥。



![程序员反应图：不要重构去复制](https://iili.io/CuzarVj.png)
> 一行 grep 下去，才知道自己装了个什么东西



第三步：检查持久化脚本。在 macOS 上，查看以下路径：

- ~/Library/LaunchAgents/com.apple.sysmond.plist
- ~/.config/.smt
- ~/.config/.smtk

这些文件名故意模仿系统组件和遥测服务，肉眼扫过不容易发现异常。如果存在，删除它们。

第四步：运行 Cursor 官方提供的 remediate-macos.sh 脚本（适用于 macOS 用户）。

第五步：轮换凭据。假设这台机器上能访问到的所有凭据——Git 令牌、SSH 私钥、云服务 API 密钥——都已经泄露。从一台可信的设备上轮换它们。

第六步：检查网络流量。如果之前有反向隧道建立成功，攻击者可能已经获得了一定的访问能力。查看系统的网络连接记录，寻找异常的出站连接。

## 结论

官方插件商城不是免死金牌。

Cursor Marketplace 的名字前面加了「官方」两个字，但这次事件证明，这个名字只能保证商城归 Cursor 运营，不能保证每一个包的内容都经过 Anthropic 验证。发布渠道的信任背书，不等于包本身的真实性背书。

这件事留给开发者的判断很明确：在 X 条件下（使用的是官方商城、安装的是热门开源扩展、且扩展具有系统级权限），你应该在升级后做至少一次自动化扫描和一次手动核查；当条件变化为（扩展涉及 SSH、凭据管理或远程执行能力），信任链条就需要手动验证而不是默认接受。

今天就能做的三件事：更新扩展到 2.1.314，grep 一下 authorized_keys，检查 LaunchAgents 目录。花十分钟，比事后补救的成本低得多。

## 66 行恶意代码到底做了什么

Cursor 安全公告披露，攻击者没有重打包整个扩展，只修改了一个文件。在 Claude Code 2.1.313 扩展的主 JavaScript 文件头部插入了 66 行代码，插件其余部分保持原样，用户感觉不到异常，只要 Cursor 加载这个扩展，恶意脚本就自动执行。



![程序员系列表情：谁TM改了我代码](https://iili.io/n9zejY7.png)
> 插件商城里埋雷



### 信息采集：主机名、Git 邮箱、公网 IP、环境变量名

第一层动作是侦察。脚本读取主机名、系统架构、home 路径、当前工作目录，再通过 git config 获取关联邮箱，最后 curl 一个公网 IP 接口拿到出口 IP。环境变量这一步值得注意——官方说明只收集变量名，不收集变量值，目的是降低触发杀毒规则的概率，同时留下足够的指纹用于后续定向。

### SSH 后门：注入 svc-telemetry 公钥，尝试反向隧道

第二层动作是安装钥匙。脚本向 `~/.ssh/authorized_keys` 追加一条标记为 `svc-telemetry` 的公钥。这个名字刻意伪装成遥测服务，视觉上不容易被一眼识别。随后尝试在本地启动 SSH 服务，并打开一条反向隧道，让远端攻击者可以直接从外部连入。

### 持久化：开机自启脚本每约 60 秒重试连接

第三层是留后路。macOS 上脚本写入了 LaunchAgents 相关路径和 `~/.config/.smt`、`~/.config/.smtk` 两个目录，Windows 上注册了开机自启项。这些持久化机制每隔约一分钟重试一次连接，只要 SSH 端口打开，攻击者就能恢复访问。



![恶意代码执行链路](https://iili.io/nrXMJbn.png)
> 恶意代码执行链路



### 关键细节：多数机器因 SSH 未开而远程失败，但本地信息已泄露

Cursor 确认，大多数 macOS 和 Windows 机器默认未开启 SSH 远程登录服务，因此攻击者的反向隧道步骤在多数设备上未能成功。这意味着攻击者无法获得 Shell 访问权限。但信息收集这一步在扩展加载时就已经完成，主机名、邮箱、公网 IP 这些字段已经上传到攻击者的服务器。更需要注意的是，持久化脚本一旦写入磁盘，即使扩展被卸载，那把 SSH 钥匙和定时重试逻辑仍然留在系统里。

## 为什么选官方商城，而不是直接盗链

### 信任锚转移：用户默认信任 Marketplace 名称

这款恶意扩展的包名、版本号、展示名称都与官方 Claude Code 扩展完全一致。用户从 Cursor Marketplace 安装，天然带有信任背书。安全研究人员指出，这类攻击之所以在官方商城得手，是因为用户不再逐个核对发布者签名，而是依赖平台审核。

### 供应链的攻击面收缩：只攻一个入口就够了

攻击者不需要破解 Anthropic 的发布系统，也不需要绕过 VS Code 的验证机制，只要把恶意包塞进 Cursor Marketplace 这一条链路就完成了分发。攻击面从整个 AI 编程工具的生态收敛到一个入口，这是典型的供应链侧翼战。

### 更狠的是，你以为是 Anthropic 在更新，实际上是陌生人

扩展名称叫 Claude Code，用户以为是 Anthropic 在维护，其实包根本不是 Anthropic 发布的。Cursor 自己也在公告里反复强调这一点。这种命名混淆本身就是攻击的一部分，它把技术判断变成了品牌信任，而信任一旦被利用，验证成本就变得很高。

## 攻击者的技术取舍

### 66 行完成四件事，没有花哨的工具链

从技术角度看，这 66 行代码没有任何第三方依赖，只用 Node.js 原生模块完成信息收集、文件操作和网络请求。这种极简设计降低了编译风险，也减少了被发现异常行为的可能性。

### 环境变量只取名字不取值，减少误报概率

取变量名比取变量值更安全——前者几乎不可能包含敏感字符串，不会触发终端安全软件的高危告警，但后者仍能提供足够的指纹用于追踪设备归属。

### SSH 失败不等于全失败：本地持久化机制仍在运行

攻击目标不是立即拿到远程 Shell，而是先埋下一把钥匙，再等用户主动开启 SSH 服务或者手动运行某个远程调试命令。钥匙一旦到位，等待就变成了主要策略。对于企业开发者的机器来说，SSH 服务被管理员临时打开的概率远高于个人电脑。

## 为什么能上架：供应链攻击换了个入口

攻击者没有入侵 Anthropic 的任何系统，也没有窃取 Anthropic 的发布凭证。根据 Cursor 的安全公告和 X 上陈成的分析，恶意包是通过直接利用 Cursor Marketplace 的发布权限被替换上去的。官方至今没有公开说明是发布流程哪个环节出了问题，只提到审计了访问记录、轮换了密钥、重建了市场。

这不是第一次类似手法的前科。

Nx Console 在 2022 年就因为开发者账号泄露导致扩展被篡改，最终同时传播到 VS Code 和 Open VSX 两个市场。那次攻击面和这次类似，都是利用了官方市场的分发通道，区别只在于传播路径更广。

信任锚发生了转移。开发者习惯在 Cursor Marketplace 里搜索「Claude Code」，看到发布者名称和版本号匹配就点击安装。官方商城的名字本身就是信任背书，而攻击者不需要攻破 Anthropic 就能获得这种信任。供应链的攻击面因此收缩到了一个入口。



![恶意扩展上架路径](https://iili.io/nrXMi22.png)
> 恶意扩展上架路径


AI 编程工具链的插件依赖比传统 IDE 更重。

Claude Code 本身是一个终端原生工具，但它通过 VS Code 扩展的形式进入 Cursor 生态，这本身就意味着一个额外的信任层。开发者在安装时默认信任 Marketplace 的审核机制，而攻击者只需要绕过这一层就够了。Cursor 后续宣布将逐步引入扩展签名验证，但目前的审核模型仍停留在事后响应阶段。
